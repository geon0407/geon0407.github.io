> ## AWQ: ACTIVATION-AWARE WEIGHT QUANTIZATION FOR ON-DEVICE LLM COMPRESSION AND ACCELERATION

arXiv : [https://arxiv.org/pdf/2306.00978](https://arxiv.org/pdf/2306.00978)

---

### ◆ 해결하고자 하는 문제

- LLM을 Edge Device(ex. PC, Phone) 내에서 구동하길 원함.  
∵ 서버와의 통신 간 지연 X, 실시간 작업에 유리(ex. 드론, 차량의 자율 주행), 클라우드 인프라 운용 Cost↓ 등의 장점 有

- LLM은 가진 Parameter가 너무 많아서 Edge Device의 한정된 컴퓨팅 자원으로 구동하기 제한됨.  
: 특히, decode 단계에서는 token 생성 시 거대한 weight를 반복해서 읽어야 하므로 memory bottleneck이 심함. **| 참고 : \[Fig 3.(a), (b)\] |**  
  ∴ 모델의 Weight를 Quantization하여 메모리 자원 활용성 증가 필요. (Weight는 학습 이후로 변하지 않음.)
  ![image.png](/uploads/2026/11/8ab1e188485eaceebdeb55c0.png)

- 0.1% FP16 유지 정도로는 model의 크기가 유의미하게 증가하지 않지만 mixed-precision이 하드웨어적 비효율을 야기  
∴ Weight의 precision을 모두 INT4로 통일하길 원함.

### ◆ 아이디어

- 실험적으로 Activation 크기 기준 0.1% \~ 1%의 가중치만 FP16으로 보호해도 양자화 성능이 크게 개선되어 FP16에 근접함. (Weight 크기 기준·무작위 선택은 효과 미미) **| 참고 : \[Table 1\] |**
  ![image.png](/uploads/2026/11/13083288a6637289c44075ee.png)
- Activation이 큰 channel에 연결된 salient weight를 scaling해서 quantization error 줄임.  
: Activation 크기를 줄인 만큼 Weight 크기를 키워 연산 결과는 동일하지만 Quantization 해도 Weight의 정보가 잘 유지됨.

- Scale factor s가 지나치게 크면 weight의 quantization range가 넓어져 다른 weight들의 resolution이 나빠지는 Trade-Off 有  
∴ 적당한 크기의 s를 결정하는 것이 중요함.

- s는 grid search로 결정. (s = sₓᵅ, α\* = argmin₍α₎ L(sₓᵅ), sₓ : channel별 activation 크기의 평균, α ∈ \[0, 1\])  
작업 과정 : α → sₓᵅ 계산 → Scaling 적용 → Per-Group으로 양자화 → 양자화 전 XW와 오차 계산 → grid search로 α 결정

### ◆ 결과

- Weight에 접근하는 양이 Activation에 접근하는 양보다 훨씬 큼. (Activation에 비해 Attention 단계에서 79배, FFN 단계에서 1700배)  
∴ Weight-only quantization이 on-device LLM에서 더욱 효과적임. **| 참고 : \[Fig 3.(c)\] |**

- Regression, Gradient Descent, Backpropagation 등의 방법을 사용하지 않으므로 calibration data에 영향을 받을 위험이 적음.
- 실제 실험적으로 GPTQ에 비해 약 10배 적은 calibration data만으로 더 좋은 성능을 얻을 수 있었으며, 서로 다른 calibration data를 사용했을 때 GPTQ에 비해 성능 편차가 적었음. **| 참고 : \[Fig. 8\] |**
